BAGIAN I. STANDARD OPERATING PROCEDURE (SOP)
1. Sistem Penomoran Dokumen &amp; Kontrol Arsip PT Nirwana Bhumi Energi
1.1 TUJUAN (OBJECTIVES)
Prosedur Operasional Standar (SOP) ini diterbitkan dengan tujuan utama:
1. Menetapkan standarisasi format penomoran surat dan dokumen resmi di lingkungan PT Nirwana Bhumi Energi (NBE) agar terstruktur, seragam, dan mudah ditelusuri.
2. Menjamin kepatuhan terhadap prinsip integritas data SATU KODE UNTUK SATU DOKUMEN (1 Kode = 1 Dokumen) guna mencegah terjadinya duplikasi nomor dokumen atau tumpang tindih arsip.
3. Mengintegrasikan penerbitan dokumen langsung ke penyimpanan awan (Google Drive) korporat secara otomatis melalui fitur Tombol Fix Kode dan Bot Google Apps Script yang membuat subfolder khusus dan menyimpan berkas.
4. Mengatur alur revisi dokumen terkontrol dengan penamaan otomatis berkas (contoh: -rev1, -rev2) serta pencatatan terstruktur pada indeks revisi (Revision Index).
5. Menyediakan mekanisme penataan dokumen masa lalu (backdating) tanpa merusak keabsahan nomor urut berjalan.
1.2 RUANG LINGKUP (SCOPE)
Prosedur ini berlaku mengikat untuk seluruh unit kerja, divisi, dan jajaran manajemen di lingkungan PT Nirwana Bhumi Energi, yang mencakup:
• Seluruh Dokumen Sistem Manajemen Terintegrasi: Standard Operating Procedure (SOP), Work Instruction / Instruksi Kerja (WIK), Manual Mutu &amp; K3 (MNL), serta Kebijakan Perusahaan / Policy (KB).
• Seluruh Divisi Operasional &amp; Korporat: Divisi General/Umum (GNR), Engineering (ENG), Operation/Pembangkit (OPR), dan Finance/Keuangan (FNC).
• Seluruh Pejabat Otoritas Pengesahan: President Director (CEO), Technical Director (CTO), Operational Director (COO), dan Finance Director (CFO).
• Seluruh Media Penyimpanan Arsip: Aplikasi Web NBE (IndexedDB/LocalStorage), Google Drive Korporat (Folder Utama ID: 1ny_1VhXfSaNrj_XdoOsC7V7BO-z0K8eF), dan Salinan Fisik Terarsip.
1.3 REFERENSI &amp; DASAR HUKUM
Penyusunan prosedur ini mengacu pada:
1. ISO 9001:2015 Klausul 7.5: Informasi Terdokumentasi (Documented Information - Pembuatan, Pembaruan, dan Pengendalian).
2. Prosedur Baku Resmi PT Nirwana Bhumi Energi No: 0001-SOP-GNR-CEO-IX-2026 (Documents and Records Control Procedure).
3. Kebijakan Manajemen Terintegrasi PT Nirwana Bhumi Energi No: 0001-KB-GNR-CEO-X-2026.

🛑 KETENTUAN MUTLAK: ATURAN KETAT UNIK: 1 KODE DOKUMEN = 1 DOKUMEN SAJA
Satu kode dokumen HANYA boleh berlaku untuk 1 dokumen saja di seluruh sistem PT Nirwana Bhumi Energi. Sistem secara otomatis memverifikasi keunikan kode. Jika kode terdeteksi telah terdaftar sebelumnya, sistem akan memblokir tombol pendaftaran dan menampilkan peringatan dokumen duplikat beserta detail dokumen pemilik aslinya.

3. Kebijakan Tombol &quot;Fix Kode&quot; (1x Klik) &amp; Auto-Folder Google Drive
Untuk memastikan kepastian penomoran sebelum dokumen final didistribusikan, sistem dilengkapi mekanisme Tombol &quot;Fix Kode&quot; dengan tata kelola sebagai berikut:
1. Aturan Klik Tunggal (1x Klik): Tombol &quot;Fix Kode&quot; yang terletak di samping tombol &quot;Copy Kode&quot; HANYA BISA DIKLIK 1 KALI per setiap kode dokumen baru.
2. Penguncian Status Otomatis: Saat tombol Fix diklik, tombol seketika terkunci (disabled) dan berubah label menjadi &quot;Fix Terkunci&quot; dengan aksen warna hijau.
3. Pemanggilan Otomatis Google Apps Script Bot: Sistem web secara otomatis mengirimkan sinyal ke Webhook Bot dengan parameter action: &quot;create_folder&quot; dan nama folder sesuai kode surat.
4. Pembuatan Subfolder Google Drive: Bot secara otomatis membuat subfolder baru di dalam Folder Utama Perusahaan (Target Folder ID: 1ny_1VhXfSaNrj_XdoOsC7V7BO-z0K8eF) dengan nama persis sesuai kode surat tersebut.
5. Penyimpanan ID &amp; URL Folder: Sistem menangkap ID dan tautan folder Google Drive yang dikembalikan bot dan menautkannya ke dokumen.
6. Notifikasi &amp; Tautan Cepat: Muncul banner hijau notifikasi sukses dengan tautan langsung &quot;Buka Folder Drive&quot; sehingga pengguna dapat langsung meninjau folder tersebut.
7. Reset Dinamis Terkendali: Jika pengguna mengubah salah satu parameter (kategori, divisi, approver, bulan, atau tahun) sehingga menghasilkan kode surat baru, tombol Fix akan aktif kembali secara otomatis khusus untuk kode baru tersebut.

4. Prosedur Revisi Dokumen Terkendali &amp; Penamaan Otomatis (-revX)
Dokumen yang telah diterbitkan dan memerlukan penyesuaian wajib mengikuti tata cara revisi terkontrol sebagai berikut:
1. Akses Tombol Revisi: Tombol &quot;Revisi&quot; tersedia secara mencolok di setiap baris dokumen pada Dashboard, Tabel Dokumen Desktop, Kartu Mobile, dan Modal Rincian Dokumen.
2. Modal Unggah Dokumen Revisi: Saat tombol Revisi ditekan, sistem membuka modal terdedikasi yang berisi formulir unggah berkas revisi (drag &amp; drop), input tanggal revisi, nama perevisi, dan catatan ringkasan revisi.
3. Penamaan Otomatis Berkas (-rev1, -rev2, dst): Sistem secara otomatis mengubah nama berkas yang diunggah menjadi format baku: [KodeSurat]-rev1.pdf untuk revisi pertama, [KodeSurat]-rev2.pdf untuk revisi kedua, dan seterusnya.
4. Penyimpanan ke Subfolder yang Sama di Google Drive: Berkas revisi otomatis diunggah dan disimpan langsung ke dalam folder Google Drive yang SAMA dengan berkas surat aslinya, sehingga seluruh riwayat versi dokumen tersimpan rapi dalam satu wadah arsip.
5. Pembaruan Status &amp; Indeks Revisi: Sistem memperbarui nomor revisi dokumen (menjadi Rev 1, Rev 2, dst.), memperbarui tautan berkas utama ke versi terbaru, dan mencatat entri riwayat ke dalam tabel &quot;Revision Index&quot; yang berisi tanggal, nama perevisi, dan deskripsi perubahan.

5. Prosedur Penghapusan Dokumen &amp; Retensi Arsip Google Drive
Untuk menjaga kerapian basis data sekaligus mencegah hilangnya data penting secara sepihak, penghapusan dokumen diatur sebagai berikut:
• Konfirmasi Berlapis: Penghapusan hanya dapat dilakukan oleh pengguna yang memiliki otoritas dan wajib mengonfirmasi dialog peringatan.
• Sinkronisasi Sampah Google Drive (setTrashed): Saat dokumen dihapus dari sistem, Bot Google Apps Script otomatis memindahkan subfolder surat beserta seluruh berkas di dalamnya ke Tempat Sampah Google Drive (setTrashed = true) sehingga berkas tidak lagi tampil di folder aktif namun masih dapat dipulihkan oleh administrator jika terjadi kekeliruan.
• Audit Trail Permanen: Setiap aksi penghapusan dokumen dicatat secara permanen di menu &quot;Log Aktivitas &amp; Audit Trail&quot; lengkap dengan nama pelaku, tanggal, dan kode dokumen yang dihapus.

2. Rincian Langkah Kerja (Detailed Operational Steps)
Workflow A: Penerbitan &amp; Penomoran Dokumen Baru
Langkah 1: Buka aplikasi web Sistem Penomoran &amp; Kontrol Dokumen PT Nirwana Bhumi Energi.
Langkah 2: Pilih menu &quot;Daftarkan Surat Baru&quot; pada sidebar eksekutif.
Langkah 3: Langkah 1 Form: Pilih Kategori Dokumen (SOP / WIK / MNL / KB), Divisi Penerbit (GNR / ENG / OPR / FNC), dan Otoritas Pengesah (CEO / CTO / COO / CFO).
Langkah 4: Langkah 2 Form: Tentukan Tanggal Surat. Sistem secara otomatis mengonversi bulan ke angka Romawi dan menetapkan tahun berjalan.
Langkah 5: Periksa Live Code Display. Pastikan tidak ada peringatan duplikasi. Gunakan tombol &quot;Copy Kode&quot; jika ingin menyalin kode ke clipboard.
Langkah 6: Klik tombol &quot;Fix Kode&quot;. Sistem mengunci tombol menjadi &quot;Fix Terkunci&quot;, memanggil Bot Google Apps Script, membuat subfolder baru bernama kode tersebut di Google Drive perusahaan, dan menampilkan banner notifikasi sukses.
Langkah 7: Langkah 3 Form: Isi Judul Dokumen, Nama Pembuat / Pengaju, Ringkasan Isi Surat, dan unggah berkas fisik (PDF).
Langkah 8: Klik tombol &quot;Daftarkan &amp; Simpan Dokumen Resmi&quot;. Berkas otomatis diunggah ke subfolder Google Drive yang baru dibuat, dokumen tersimpan ke IndexedDB/LocalStorage, dan aksi dicatat ke Log Aktivitas.

Workflow B: Pelaksanaan Revisi Dokumen Terkendali (-revX)
Langkah 1: Identifikasi dokumen yang memerlukan revisi melalui Dashboard atau Menu Pencarian Dokumen.
Langkah 2: Klik tombol &quot;Revisi&quot; (berwarna kuning/oranye) pada baris dokumen atau modal detail.
Langkah 3: Pada modal &quot;Unggah Dokumen Revisi&quot;, unggah berkas revisi baru (format PDF/Docx).
Langkah 4: Sistem secara otomatis mengubah nama berkas menjadi [KodeSurat]-rev1.pdf (atau nomor revisi selanjutnya jika sudah pernah direvisi).
Langkah 5: Isi Tanggal Revisi, Nama Perevisi, dan Catatan Rinci Perubahan yang dilakukan.
Langkah 6: Klik tombol &quot;Simpan &amp; Terapkan Revisi&quot;. Berkas revisi diunggah ke subfolder Google Drive yang SAMA dengan berkas aslinya. Sistem memperbarui nomor revisi dokumen dan menambahkan entri ke tabel &quot;Revision Index&quot;.

1. Script Bot Google Apps Script Siap Pakai
Kode skrip Google Apps Script di bawah ini merupakan kode resmi siap salin untuk dipasang pada Google Apps Script Web App perusahaan. Skrip ini menangani tiga aksi utama: create_folder, upload, dan delete:
/**
 * BOT GOOGLE DRIVE - PT NIRWANA BHUMI ENERGI (NBE)
 * Target Folder ID: 1ny_1VhXfSaNrj_XdoOsC7V7BO-z0K8eF
 */
var TARGET_FOLDER_ID = &quot;1ny_1VhXfSaNrj_XdoOsC7V7BO-z0K8eF&quot;;

function doPost(e) {
  try {
    var data = JSON.parse(e.postData.contents);

    // AKSI 1: BUAT SUBFOLDER BARU (TOMBOL FIX KODE)
    if (data.action === &quot;create_folder&quot;) {
      var folderName = data.folderName || data.documentCode || &quot;Dokumen_NBE&quot;;
      var parentFolder = DriveApp.getFolderById(TARGET_FOLDER_ID);
      var existing = parentFolder.getFoldersByName(folderName);
      var targetFolder = existing.hasNext() ? existing.next() : parentFolder.createFolder(folderName);
      targetFolder.setSharing(DriveApp.Access.ANYONE_WITH_LINK, DriveApp.Permission.VIEW);

      return ContentService.createTextOutput(JSON.stringify({
        status: &quot;success&quot;,
        folderId: targetFolder.getId(),
        folderUrl: targetFolder.getUrl()
      })).setMimeType(ContentService.MimeType.JSON);
    }

    // AKSI 2: HAPUS SURAT &amp; FOLDER (PINDAH KE SAMPAH)
    if (data.action === &quot;delete&quot;) {
      if (data.folderId &amp;&amp; data.folderId !== TARGET_FOLDER_ID) {
        DriveApp.getFolderById(data.folderId).setTrashed(true);
      }
      return ContentService.createTextOutput(JSON.stringify({
        status: &quot;success&quot;
      })).setMimeType(ContentService.MimeType.JSON);
    }

    // AKSI 3: UPLOAD BERKAS (AWAL &amp; REVISI -rev1, -rev2, dst)
    var folder = DriveApp.getFolderById(data.folderId || TARGET_FOLDER_ID);
    var fileName = data.fileName || &quot;dokumen.pdf&quot;;
    if (data.isRevision &amp;&amp; data.documentCode) {
      fileName = data.documentCode + &quot;-rev&quot; + (data.revision || 1) + &quot;.pdf&quot;;
    }

    var blob = Utilities.newBlob(Utilities.base64Decode(data.base64), data.mimeType || &quot;application/pdf&quot;, fileName);
    var file = folder.createFile(blob);
    file.setSharing(DriveApp.Access.ANYONE_WITH_LINK, DriveApp.Permission.VIEW);

    return ContentService.createTextOutput(JSON.stringify({
      status: &quot;success&quot;,
      fileId: file.getId(),
      viewUrl: file.getUrl()
    })).setMimeType(ContentService.MimeType.JSON);

  } catch (err) {
    return ContentService.createTextOutput(JSON.stringify({
      status: &quot;error&quot;,
      message: err.toString()
    })).setMimeType(ContentService.MimeType.JSON);
  }
}
